# Клуб «Изумруд»

Сайт клуба развития мышления: членство по подписке 10 000 ₽ в месяц, лекции в видео и аудио, статьи, фото встреч. Работает как PWA — участники добавляют сайт на экран телефона, и он открывается как приложение.

Каркас MVP по ТЗ: вход по коду на email, оплата и автопродление через ЮKassa, отмена в один клик, каталог лекций, продолжение просмотра с места остановки, фоновый аудиоплеер, статьи, альбомы, push-уведомления, админка Directus.

## Стек

| Часть | Технология |
| --- | --- |
| Сайт и API | Next.js 15, React 19, TypeScript, Tailwind CSS 4 |
| База | PostgreSQL 16, Drizzle ORM |
| Админка | Directus 11 поверх той же базы |
| Фоновые задачи | Node.js-процесс `worker/` (продление, напоминания, уведомления) |
| Платежи | API ЮKassa v3: автоплатежи, чеки 54-ФЗ |
| Видео | Kinescope (демо-режим — тестовый HLS-поток) |
| Аудио, фото | Локальная папка или S3 (Yandex Object Storage), подписанные ссылки |

В ТЗ была указана Prisma, в коде — Drizzle: ему не нужен отдельный бинарный движок, а миграции — обычный SQL в папке `drizzle/`.

## Запуск на своём компьютере

Нужны Node.js 20+ и PostgreSQL 16. Для демо-контента — ffmpeg и Python 3 с Pillow (необязательно).

```bash
npm install
cp .env.example .env          # укажите DATABASE_URL, остальное можно оставить
npm run db:migrate            # создать таблицы
npm run db:seed               # демо-лекции, статьи, альбомы
npm run dev                   # сайт: http://localhost:3000
npm run worker                # в соседнем окне: продления и уведомления
```

Без ключей всё работает в демо-режиме:

- **Почта.** Код входа показывается прямо в форме и печатается в лог.
- **Оплата.** Вместо ЮKassa открывается страница `/dev/mock-pay` с кнопками «Оплатить» и «Отказаться», деньги не списываются. Чтобы проверить неудачное автосписание, войдите с адресом вида `name+fail@example.ru`.
- **Видео.** Играет тестовый HLS-поток.

В `next start` (production) демо-оплата выключена, пока не задано `ALLOW_MOCK_PAYMENTS=1`.

## Размещение на сервере

Сервер в России (Яндекс Cloud, Selectel и т. п.) — персональные данные по 152-ФЗ должны храниться в РФ.

```bash
cp .env.example .env     # заполнить всё, особенно APP_URL, APP_SECRET, ключи ЮKassa, DIRECTUS_*
docker compose up -d --build
docker compose exec app npm run directus:setup     # один раз
```

Поднимутся четыре контейнера: `db`, `app` (сайт, порт 3000, при старте применяет миграции), `worker`, `directus` (админка, порт 8055). Наружу их выставляет обратный прокси с HTTPS, например Caddy:

```
club.example.ru  { reverse_proxy localhost:3000 }
admin.club.example.ru { reverse_proxy localhost:8055 }
```

Для `admin.` задайте `DIRECTUS_PUBLIC_URL=https://admin.club.example.ru`. При первом входе Directus попросит указать владельца проекта (лицензия BSL: бесплатно для организаций с оборотом до $5 млн).

Демо-контент на сервере не нужен. Если всё же хотите его: `docker compose exec app npm run db:seed`, затем снова `npm run directus:setup`.

## ЮKassa

1. Зарегистрируйте магазин, получите `shopId` и секретный ключ → `YOOKASSA_SHOP_ID`, `YOOKASSA_SECRET_KEY`.
2. **Сразу напишите менеджеру ЮKassa и попросите включить автоплатежи** — по умолчанию они работают только в тестовом магазине.
3. Подключите чеки (сервис «Чеки от ЮKassa» или облачную кассу). Ставку НДС и признаки чека согласуйте с бухгалтером: `YOOKASSA_VAT_CODE`, `YOOKASSA_RECEIPTS`.
4. В личном кабинете ЮKassa → HTTP-уведомления укажите `https://<домен>/api/webhooks/yookassa` и события `payment.succeeded`, `payment.canceled`, `refund.succeeded`.
5. Проверьте всё сначала с ключами тестового магазина.

Как устроена оплата:

- Первый платёж сохраняет карту или счёт СБП, только если участник отметил отдельную галочку согласия на автосписание.
- Фоновый процесс раз в 5 минут: за 3 дня до списания отправляет напоминание, в момент окончания периода создаёт автоплатёж, при отказе даёт 3 дня доступа и делает повторы через 24 и 48 часов.
- Вебхуку сайт не доверяет: по ID из уведомления запрашивает платёж у ЮKassa. Повторные уведомления ничего не меняют.
- Отмена автопродления и удаление карты сразу отключают способ оплаты — по нему больше не создаётся платежей (376-ФЗ).
- Возвраты делаются в личном кабинете ЮKassa, сайт отмечает их в истории платежей.

## Видео: Kinescope

1. Загрузите видео в Kinescope, скопируйте ID видео в поле «ID видео» лекции в админке.
2. В настройках проекта Kinescope ограничьте воспроизведение своим доменом — иначе встраивание будет работать на любом сайте.
3. В `.env`: `VIDEO_PROVIDER=kinescope`.

Сайт отдаёт ссылку на плеер только участнику с активным членством и рисует поверх видео водяной знак с email участника.

## Аудио, фото и файлы

- Файлы, загруженные в админке, Directus кладёт в общий том `storage`; сайт отдаёт их по ссылкам, которые живут 1–4 часа.
- Для S3 (Yandex Object Storage): `STORAGE_DRIVER=s3` и `S3_*` в `.env`, а Directus настройте на тот же бакет (`STORAGE_LOCATIONS=s3`, `STORAGE_S3_*`).
- Аудиоверсия из видеофайла: `npm run audio:extract -- lecture.mp4 slug-lekcii` (нужен ffmpeg).

## Push-уведомления

`npm run push:keys` → публичный ключ в `NEXT_PUBLIC_VAPID_PUBLIC_KEY`, приватный в `VAPID_PRIVATE_KEY`. Участник включает уведомления в профиле. На iPhone push работает только для сайта, добавленного на экран «Домой» — на главной есть подсказка.

## Админка

После `npm run directus:setup` в Directus:

- **Лекции, Статьи, Встречи (фото), Темы** — контент. Материал виден участникам, когда статус «Опубликовано» и наступила дата публикации; в эту дату участникам уходит уведомление.
- **Участники, Подписки, Платежи, Согласия** — для администратора, только смотреть. Редактировать подписки вручную не стоит: продление и списания ведёт фоновый процесс.
- Роль **«Редактор»** — доступ только к контенту и файлам. Создайте пользователя с этой ролью для того, кто загружает лекции.
